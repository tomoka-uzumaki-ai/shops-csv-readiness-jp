# メルカリShops 独自注文連携の旧参照候補パック v0.1.0

無料・非公式。対象は自分で注文連携を保守する開発担当です。既存ECサービスを利用するだけの店舗は、まず提供元の対応状況を確認してください。このパックはAPIへ接続せず、トークン・ショップID・顧客データを要求しません。

## 3分で最初の担当箇所を出す

Python 3.9以上の標準ライブラリのみ。ZIPを展開し、そのフォルダでまず架空例を実行します。

```sh
python3 scan_order_api.py examples/legacy.graphql --json
# 次は、自分に読取権限がある実ソースの狭い範囲だけ
python3 scan_order_api.py /path/to/authorized/source --json
```

出力はファイル名・行番号・候補API名・確認する仕事だけです。ソース本文やセル値は出力しません。ソースを変更せず、ネットワークへ送りません。JSONを他者に渡す場合は、ファイル名・パス自体が機密にならないか確認してください。文字コードはUTF-8（BOM可）。.git、node_modules、vendor、dist等は対象外。5000ファイル、1ファイル1MBを超える範囲は停止または省略します。rootのsymlinkは拒否し、内部のsymlinkファイルも追跡しません。

|終了コード|意味|次にすること|
|---|---|---|
|0|読めた対象に旧名称候補なし|安全・互換性・移行完了の証明ではない。動的生成、生成ファイル、別設定等を担当者が確認|
|2|旧名称候補あり|コメント・未使用コードの誤検出を除き、実際の呼出箇所を原典と照合|
|3|検査不完全（未読・巨大ファイル・対象なし）|範囲/文字コードを確認。検出なしとは扱わない|
|1またはargparseの2|読取中断または実行引数不備|エラー表示を確認。移行判断に使わない|

コード2は候補ありと引数不備の両方で使われます。JSON reportが得られたか、stderrの引数エラーかを区別してください。自動ジョブはreport.scan_statusとfindingsも確認してください。

## 候補を担当者の受入検査へ変える

1. 実際に使う旧名称だけを自分の担当票へ転記する。該当file/line、呼出用途、担当者、次の確認を残す。
2. 対象処理に関係する架空契約を見る。数量、複数商品、部分取消、分割発送、旧messages null、Webhook再送の6例を同梱しています。
3. fixtures.jsonは実APIレスポンスではありません。自分のアプリが購入/残/発送/取消を排他的な状態へ正規化する設計を仮定した例です。APIの複数量欄を直接合算しないでください。synthetic_event_keyもMercariの実ヘッダ/IDではありません。
4. 独自adapter、現在の原典、権限あるSandboxで、実payload/ページング/永続化/再送/状態遷移を検収した後に担当者が切替を決めます。このパックは本番を改修しません。

```sh
python3 test_scanner.py
python3 verify_fixtures.py
```

14候補抽出境界と6架空契約を検証できます。検証コマンドはパック内へ結果JSONを作りますが、scan_order_api.py自体は書き込みません。実APIの互換性や有料需要のテストではありません。
